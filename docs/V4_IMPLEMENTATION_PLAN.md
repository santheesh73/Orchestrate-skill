# V4 implementation plan

This plan preceded implementation. The V4 brief initially prohibited commits and
pushes without permission. The maintainer subsequently requested publication to
the existing branch; that later instruction authorizes committing and pushing.

## Dependency order

1. Record unchanged full regression baseline and pinned reference source audit.
2. Add bounded records/report helpers and source-located challenge intelligence.
   Preserve the original extraction helper and all ten original checkers.
3. Extend evaluation through a wrapper: explicit input schemas, replay/metamorphic
   relations, injected controls, required checks and JSON/Markdown reporting.
4. Add configurable evidence-based local estimates, immutable experiment records,
   append-only decision history and a deterministic evidence-driven mentor.
5. Add implementation/experiment-aware interview questions and factual-claim checks.
6. Add fail-closed edition release gating, reproducibility manifests, redacted
   secret findings and explicit manual-review evidence. No automatic uploads.
7. Add optional workflow policy gates and GEMINI instruction checkpointing;
   preserve existing checkpoints, transitions and bounded recovery behavior.
8. Add explicit, owned upgrade-backup restoration with dry-run, conflict checking,
   transaction rollback and an approval flag for applying the restore.
9. Integrate implemented commands into the existing orchestrate-toolkit CLI;
   retain its name to avoid collision with the optional reference toolkit command.
10. Add a canonical V4 reference and nine-component architecture contract, update
    the educational README and installation/evaluation/security/troubleshooting guides.
11. Run focused tests after each component, final full regressions, original smoke,
    wheel/module checks, documentation checks and pinned identical-input benchmarks.
12. Record exact outcomes, fingerprints, missing capabilities and acceptance status.

## Acceptance policy

Every major component needs positive and failing/unknown controls. Checkers never
execute participant code implicitly. UNKNOWN is distinct from PASS; missing or
stale mandatory evidence prevents local READY. Manual attestations remain supplied
review evidence rather than signed or independently authenticated facts. A local
score is always heuristic and shows missing weights and uncertainty.

Live agent activation, model interview assessment and hidden official performance
cannot be fabricated. Implement their safe offline support and report them as
unverified where no genuine execution evidence is available. No multi-agent runtime,
paid API or automatic destructive/external workflow is needed for the upgrade.
